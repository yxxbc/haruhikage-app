## 2. 产品收敛：保留什么，删除什么

推荐成品定位：**不需要网易账号的桌面音乐播放器；歌曲来自平台曲库，播放地址由你导入的音源解析；收藏、歌单和历史归你本地管理。**

### 2.1 核心功能

- 多平台搜索，保留平台筛选；先实现单平台筛选，五个平台齐备后再做可取消的聚合搜索。
- 我喜欢、本地歌单、最近播放、队列、随机/顺序/单曲循环、退出恢复。
- 音源导入、检查、切换、禁用、删除、手动替换与导出；能够直接使用你这份 JS。
- 音质选择、歌词及翻译、歌词偏移、封面、系统媒体键、托盘、音量、缓存和主题。
- 当前精致的封面、正在播放转场、歌词滚动/逐字效果。保留可选的律动展示，不让特效绑架基础播放。
- 匿名读取的平台榜单、专辑、歌手页保留为次级入口，能力不足的平台明确显示边界。

## 3. 你的音源文件能做什么

文件：`D:/个人资料/音乐/lx-music-source-paid-merged.js`，约 612 行。文件包含服务凭证，方案、报告和探针结果均不复制这些值。

### 3.1 已确认的接口

初始化读取 `globalThis.lx` 的 `EVENT_NAMES / on / send / request`，并最终发送 `inited`。收到 `request` 事件后，只接受 `action: "musicUrl"`。宿主传入：

```js
{
  action: 'musicUrl',
  source: 'wy',
  info: {
    type: '320k',
    musicInfo: { id: '平台原始歌曲 ID' }
  }
}
```

实际取歌曲标识的优先级为 `musicInfo.hash ?? musicInfo.songmid ?? musicInfo.id`，因此各平台适配器必须构造正确字段，不能把多个平台的无关 ID 混在同一个对象里。全部 ID 在业务边界都保留字符串，避免 JavaScript 大整数精度损失。

脚本向自己的解析服务发请求，携带 `source / songId / quality`，返回一个 HTTP(S) 播放 URL。**没有搜索、歌单、歌词、封面、时长、文件大小、格式或响度结果。** 所以仅支持导入脚本，用户仍然无法完整地搜歌和展示歌词；曲库适配是独立工程。

平台/音质声明：

| 平台标识 | 含义 | 脚本声明的音质键 |
| --- | --- | --- |
| `kw` | 酷我 | `128k, 320k, flac, flac24bit, hires` |
| `mg` | 咪咕 | `128k, 320k, flac, flac24bit, hires` |
| `kg` | 酷狗 | 上述 5 项，加 `atmos, master` |
| `tx` | QQ 音乐 | 上述 5 项，加 `atmos, atmos_plus, master` |
| `wy` | 网易云 | 上述 5 项，加 `atmos, master` |

以上表示脚本接受这些参数，不证明服务器一定返回对应音质，也不证明当前解码器能播放其结果。`flac24bit` 与 `hires` 不合并；“母带”“全景声”的名称不能用来推断真实编码或声道能力。

接口证据：脚本 `135–163`（平台/音质）、`238–267`（HTTP 回调）、`475–569`（解析/取 ID）、`577–612`（能力与初始化）。

### 3.2 已有调度与缓存，不应在 Go 里重复加一层重试风暴

脚本自带：

- 单次请求超时 5 秒，总解析预算 10 秒。
- 4 个内置 Key；每个 Key 并发上限 1，等候队列上限 50。
- 瞬时错误最多尝试 2 次；403/401、限流等另有 Key 冷却/切换规则。
- 相同平台/歌曲/音质的进行中请求合并。
- URL 缓存 30 秒，最多 512 项。

证据：脚本 `32–41,170–236,324–472,495–546`。这些是脚本内部参数，不等同于应用所有 HTTP 请求的超时。宿主应提供任务截止时间和取消边界，不再叠加一套盲目“重试三次、再降音质、再换源”。

脚本存在更新检查函数，但当前初始化路径未调用；本地探针确认启动没有发 HTTP 请求。不要根据注释中的版本、日期或开关推断服务处于可用状态。

### 3.3 本地探针覆盖

已验证：初始化能力声明和零启动请求、全部 32 组参数、未知 action/平台/音质/空 ID 拒绝、ID 优先级和长字符串保真、并发去重、30 秒缓存过期、缓存键隔离、403 换 Key、HTTP 状态优先于业务成功字段、500 终止重试、非法 URL 拒绝、字符串 JSON 响应、全部 Key 失效后有限结束。

复现文件与结果：

- `.analysis/refactor-20261106/source-contract.cjs`
- `.analysis/refactor-20261106/source-contract-results.json`

未覆盖真实超时/中断、网络代理、真实服务返回的音频、平台曲库接口、Go JS 引擎事件循环；后续必须单独补上，不能把上述探针通过写成“32 种音质播放通过”。

## 4. 当前最需要解决的机制问题

### 4.1 网易模型贯穿全链路

当前链：

```text
搜索页 -> netease.SearchPage -> []netease.Track
列表点击 -> Track.Playable -> Player.PlayQueue
Player.loadAt -> netease.SongURL / Lyrics / Fetch
netease.Stream -> 按数字 ID/网易音质命名的缓存 -> 解码/音频输出
账号喜欢/歌单 -> 网易接口
```

仅替换 `streamURL` 会留下网易 ID、网易音质、网易权限、网易歌词和缓存键。QQ 的字符串 songmid、酷狗 hash 都无法自然进入当前 `int64` 模型；不同平台相同数字 ID 还会碰撞。

### 4.2 权限检查必须改为“当前播放通路能否解析”

`Track.Playable()` 按网易 `Privilege/Fee` 判断可播（`netease.go:88–101`）。列表点击、首首可播选择、最近播放、队列和封面墙都依赖此逻辑。换成自管音源后，旧的 VIP 判断不再能代表当前播放通路。

应保留平台给出的下架/权限信息用于说明，但不继续用它拦住解析器；当前音源支持该平台与动作时允许尝试，真实失败由解析/下载/解码层返回。需统一排查所有 `.Playable()`，不能只改搜索列表一处。

### 4.3 自动 EQ 在首播路径上有实际前置工作

`loadAt -> open -> analyzeAutoEQ -> audio.NewPlayer`。自动 EQ 独立打开解码流，读取约 10 秒样本后才返回（`player.go:678–711`、`autoeq.go:151–182`）。

已确认这段工作阻挡输出创建；尚未测量它在本机、本地缓存或不同网速下的耗时，不应声称“固定多等 10 秒”。建议从关键路径移出：第一版默认不启用自动分析，保留手动 EQ；用户开启自动分析后，优先使用已缓存结果，没有结果则本次按原声播放、后台计算供下次使用，不在歌曲中途突然改音色。

### 4.4 URL 之外的元数据和下载行为不能沿用网易假设

当前 `netease.Stream` 提供 size/type/level/gain/peak；脚本仅返回 URL。宿主需要从响应、文件签名和解码头探测真实格式及长度，无法获知的数据明确标记 unknown，而非填一个默认 FLAC/320k。

当前下载走 `http.DefaultClient`、无请求 context；从头顺序落临时文件，没有 Range 读取设计（`internal/player/stream.go:29–110`）。可渐进解码并播放已到达的数据，但不等同于能立即跳到尚未下载的位置。

MP3 seek 在大小未知时会等待整份下载，已知大小时按字节比例估计位置（`stream.go:441–460`）。把 URL-only 结果直接包装成 size=0，将触发这个全量等待分支；VBR 位置准确性也需验证。`Player.Seek` 从界面路径调用底层 `audio.Player.Seek`（`player.go:497–536`）；是否会同步卡住 UI 还取决于当前 MyGo 实现，不能在未检查依赖源码和实测前断言已发生 UI 卡死。

### 4.5 过期结果被丢弃，不等于旧任务已取消

播放器有 `gen`，能防止旧歌结果覆盖新歌，但封面、歌词、解析和分析仍可能继续运行至返回（`player.go:620–708`）。页面加载也缺统一 context，多个页面 map 长驻在 `app` 中。需要任务取消、容量边界和主线程快照；保留 generation 校验作为最后一道状态一致性检查。

### 4.6 图片缓存和跨平台封面地址

图片解码、着色已有复用基础，但缓存 map 没有淘汰预算。`netease.Sized()` 无条件拼接网易 `?param=`，不能应用到 QQ/酷狗等地址或带现成 query 的签名 URL。缩图规则归属曲库适配器；图片服务仅处理图片 URL、目标尺寸、缓存和资源生命周期。

### 4.7 关闭缓存可能反而把整首歌放进内存

缓存关闭、资源过大或临时文件创建失败时，当前实现进入内存下载（`internal/player/cache.go:84–114`）。`maxPrealloc` 只约束预分配，后续仍持续 append；磁盘写失败还会整体读回内存（`stream.go:64–69,134–159`）。频谱数组按时长预先分配（`stream.go:546–548`）。这证明了内存缺少对应上限，但没有实测到本机内存峰值。

建议把“是否持久保存”和“播放时如何暂存”分开：关闭缓存仍允许有配额、播放后删除的磁盘暂存，不能无条件退到整首内存缓存。限制不可信时长、文件大小和并发数，频谱改为分段或有限窗口。高音质/长音频接入前就要解决这个边界。

### 4.8 缓存锁、设置与定时器的生命周期

缓存完成回调在下载锁内执行重命名、元数据写入和目录扫描淘汰（`stream.go:165–179`、`internal/player/cache.go:120–144,193–211`）；解码读取也使用该锁。建议缓存提交/淘汰由独立协调器执行，读取路径不持锁做目录 I/O，并增加在用租约和清空屏障，防止“刚清空又被进行中下载写回来”。实际卡顿幅度需实测。

后台加载通过闭包直接读取主线程可修改设置（`app.go:218–221`、`player.go:656–668`），应捕获加载快照并用 race 检查验证。当前 EQ 滤波器在加载时建立，而设置和增益计算可能读取新值（`ui_settings.go:275–301`、`player.go:542–570`）；必须明确即时生效还是下一首生效，并让补偿使用实际生效参数。

睡眠定时器的回调在 post 入队后没有代次校验；只 Stop timer 无法撤回已入队回调（`internal/player/sleep.go:27–60`）。重设后旧回调可能清空新状态并暂停，需以假时钟和延迟执行 post 的回归验证，而非只调定时长度。

## 5. 目标架构与包边界

保留单进程桌面 UI/播放程序；只有不受信任的 JS 放到一个受控辅助进程。避免引入 Electron、WebView、Node 运行时、插件市场、DI 框架或全局事件总线。

```text
MyGo 页面 / app 状态（主线程）
  ├─ Catalog：搜索 / 榜单 / 专辑 / 歌手 / 歌词 / 封面信息
  │    └─ 平台适配器 wy / tx / kg / kw / mg
  ├─ Library：本地收藏 / 歌单 / 历史 / 备份
  │    └─ SQLite
  ├─ SourceManager：导入 / 能力 / 选择 / 健康 / 版本
  │    └─ source-host 进程：JS 引擎 + LX 兼容宿主
  └─ Player：队列 / 状态机 / 解析协调 / 音频输出
       └─ 解析结果 -> 下载与文件缓存 -> 格式探测/解码 -> EQ/淡变 -> 系统媒体接口
```

建议目录：

```text
cmd/haruhikage/main.go            # 桌面入口；可先保留现有根 main.go，避免无效搬家
cmd/source-host/main.go          # 不依赖 MyGo/音频初始化的 JS 宿主入口
internal/domain/                # TrackRef、Track、Playlist、Quality、StreamDescriptor
internal/catalog/               # 能力接口、注册、分页、搜索请求/结果
internal/catalog/providers/wy/   # 从现有 netease 提取匿名曲库能力
internal/catalog/providers/tx/
internal/catalog/providers/kg/
internal/catalog/providers/kw/
internal/catalog/providers/mg/
internal/source/                # 文件管理、能力、选择、RPC 客户端、诊断
internal/sourcehost/             # JS event loop、LX API、HTTP/timer、资源限制
internal/library/               # SQLite 持久化、本地歌单/历史和迁移
internal/player/                # 保留并改造已有播放核心，不一次搬散所有文件
internal/app/                   # composition、主线程 UI 状态和页面
pkg/lyrics/                     # 保留解析/排字逻辑
```

依赖方向：`app -> catalog/library/source/player -> domain`；平台实现不能被播放器或 UI 直接导入；JS 宿主不读取用户资料库；domain 不依赖 MyGo、网易或具体数据库。简单操作直接调用服务，不为每个按钮制造一套 command/event/reducer。

状态建议按职责分组为 `NavigationState / SearchState / LibraryState / SourceState / NowPlayingState / Preferences`。视图只消费状态和发出操作，网络/SQL/JS/分析不在构建回调中执行。现有 `a.post` 保留为主线程入口，后台任务读取在主线程捕获的不可变设置快照，完成后核对 generation/route 再写状态。

## 6. 统一模型与最小接口

下面仅为边界示意，不是本轮已实现的 API：

```go
type TrackRef struct {
    Provider string // wy / tx / kg / kw / mg / local（如后续支持本地文件）
    ID       string // 原始 ID，不经 float64 或 int64 强转
}

type Track struct {
    Ref        TrackRef
    Title      string
    Artists    []Artist
    Album      Album
    Duration   time.Duration
    Cover      ImageRef
    PlaybackID PlaybackIdentity // 平台适配器提供给 LX 的 hash/songmid/id
}

type StreamDescriptor struct {
    URL              string
    Headers          http.Header
    RequestedQuality string
    ServedQuality    string // 不知道则为空，不能把请求值冒充实际值
    Codec            string // 探测前可为空
    Size             int64  // -1 表示未知；不能伪造已知长度
    ExpiresAt        time.Time
    Gain             *float64
    Peak             *float64
    SourceID         string
    SourceRevision   string
}

type Catalog interface {
    Capabilities() CatalogCapabilities
    Search(context.Context, SearchQuery) (SearchPage, error)
    Lyrics(context.Context, TrackRef) (Lyrics, error)
    // 榜单/专辑等按能力拆小接口，不逼每个平台实现空方法。
}

type Resolver interface {
    Capabilities() SourceCapabilities
    Resolve(context.Context, ResolveRequest) (StreamDescriptor, error)
}
```

必须统一替换的身份使用点：

- 歌曲/专辑/歌手/歌单路由，以及搜索缓存键；不能留下纯 `int64 route.id`。
- 资料库收藏、历史、歌词偏移、图片与音频缓存键。
- 当前歌曲高亮、队列去重、列表稳定 key、系统媒体信息。
- `Player.Session` 的序列化和旧版本恢复。
- 队列条目使用独立 `QueueEntryID`，同一首歌在队列里出现两次也有不同 UI 身份；歌曲身份与队列位置不混用。

跨平台同名歌曲不自动合并，平台 A 的 ID 不直接交给平台 B 音源。以后若做跨平台匹配，应有独立、可确认的匹配流程，不把模糊搜索结果作为隐式替身。

## 7. LX 音源宿主：兼容、隔离和管理

### 7.1 技术选择

推荐 **Goja + 单独的 `source-host` 辅助进程**，桌面应用通过有界 JSON 消息管道通信。Goja 是首选验证对象，尚未在本项目安装或试跑；必须先通过本脚本的真实编译、Promise/回调/timer/异常与取消 PoC，再锁版本实施。

选择理由：沿用 Go 工具链，不要求用户安装 Node；把脚本异常、死循环和内存失控从 UI/音频进程隔开；独立入口不执行 MyGo 初始化。代价是新增一个 JS 引擎依赖、一个随包发布的辅助可执行文件，以及事件循环/RPC 的实现与测试。不要把 Node VM 探针结果当作 Goja 已支持脚本的证据。

JS 单个 runtime 只在自己的 event loop 中访问。Go HTTP 回调与 timer 先投递到此循环，不能从多个 goroutine 直接调用 JS；Promise 完成、异常和关停都走同一生命周期。

### 7.2 兼容面

第一批明确支持当前脚本实际使用的：

- `lx.EVENT_NAMES`、`lx.on`、`lx.send`、`lx.request`。
- 标准 Promise、Map、Set、JSON、Date、URL 编码相关基础函数、timer 和 console。
- request 的 callback 结构：网络错误、HTTP status、headers、body；返回可取消句柄。
- `inited` 的 sources/actions/qualitys 与 `musicUrl` Promise 结果。

不会因为这份脚本可用就宣称支持“所有 LX 音源”。未读取官方 LX 实现或测试其他脚本时，不预先实现虚构的完整 ABI；需要 `utils.crypto`、Buffer、文件访问等的新脚本，明确报出缺失能力，再按真实需要扩展。

### 7.3 进程和 HTTP 约束

- 一次选择一个当前音源；可以管理多个文件，先不做自动跨源轮询。当前这一个脚本已经覆盖五个平台。
- 工作进程按需启动，不每首歌启动一次；不预先访问付费接口来做隐式健康检查。
- Windows 启动器显式隐藏窗口、无 shell、管道传输；构建/打包后验证无控制台闪现。stdout 仅承载带 request ID 的有界 RPC 消息；console/诊断走脱敏 stderr，不污染协议。
- 不暴露 require、process、任意磁盘、系统命令、应用 Cookie 或数据库路径。仅提供声明过的宿主能力。
- 按解析任务跟踪 timer、HTTP 和回调；源切换/禁用/退出时终止 worker 并释放全部资源。
- 旧 LX 接口没有通用任务取消事件。取消 Go 侧等待不应被描述成脚本内所有工作已取消；要在 PoC 中验证如何清理宿主 HTTP 与 timer、共享请求的引用计数，不能误伤仍有消费者的请求。无法立即中断的操作保留真实的有界超时，并测试快速切歌时的残留上限。
- 网络协议仅允许 HTTP(S)，关闭脚本的任意系统访问；需要内网音源时由用户显式配置许可。辅助进程隔离不等于完整 OS 沙箱，不能作此承诺。

### 7.4 音源管理交互

`导入 JS -> 静态读取元信息 -> 隔离初始化 -> 展示平台/动作/音质/联网权限 -> 设为当前音源`。可展示声明或观测到的目标域名，但不能把静态扫描结果当成脚本全部联网范围。

列表展示名称、版本、平台、状态、导入日期、当前标记和最近错误。提供重新检查、手动替换、禁用、删除、导出。删除音源不删除本地歌单；没有当前音源时仍可管理资料库，播放入口提示导入。

脚本保存到应用自己的 `sources/<SourceID>/`，保留来源路径信息和内容摘要；替换采用暂存初始化成功后原子切换，初始化失败保留旧版本。不能修改用户原始 JS，不能把脚本内 Key 拆出来写死到 Go。去掉网易账号登录不等于解析服务无需凭证，仍由原脚本管理自己的鉴权。脚本导出属于显式操作，提示导出文件包含脚本原文及其凭证，不在普通日志或备份里默默带出。

健康检查分为“初始化合同检查”和“用户主动发起的歌曲解析检查”。后者才访问真实服务；诊断默认只保留错误类别、状态码、耗时、源 ID 和 request ID，剔除凭证、查询令牌和完整签名 URL。

## 8. 曲库：与音源彻底分开

现有代码只实现网易曲库。要让 `kw/mg/kg/tx/wy` 都能从应用里正常搜歌，必须补齐另外四个平台的曲库适配，JS 脚本不会替我们完成。

实施策略：

1. 先将网易匿名搜索/详情/歌词接入统一模型，跑通现有脚本的 `wy` 播放；这是中间里程碑，不算五平台成品。
2. 逐个平台补齐搜索分页、稳定 ID、播放标识、歌词、封面；每个平台均用真实结果核对传入脚本的字段。
3. 平台具备哪些榜单/专辑/歌手功能，就登记哪些能力；UI 不显示无实现的入口。
4. 全部五个平台的基础搜索与播放链验收后，再启用聚合搜索。结果仍保留平台标识和原始 ID。
5. 歌词由曲库适配器获取和归一化。现有解析器明确实现 LRC/YRC（`pkg/lyrics/lyrics.go:38–116`），不宣称已支持 QQ QRC 或酷狗 KRC；遇到真实样本后补格式解码/解析及时间轴回归，逐字数据缺失时明确退为逐行显示。

网易的 `SongDetails/Lyrics` 部分走 EAPI（`netease.go:306–330,460–492`）。不能把“删除登录”误做成删除所有 EAPI/加密代码；应保留必要的匿名协议实现，移除账号持久化、账号注入及账号写操作。是否每个接口都能稳定匿名工作，需实请求确认。

界面无需用户账号，但平台接口仍可能限流或改变；错误按平台显示，不伪造空结果为“无歌曲”。搜索旧请求可取消，旧结果不能覆盖新关键词；输入联想应有防抖和取消，正式回车立即提交。

## 9. 本地资料库与迁移

推荐 SQLite 保存结构化音乐资料，JSON 仅保存轻量偏好设置。原因是收藏、多个歌单、条目排序、历史和搜索需要关系、事务及分页；不再每次改一首歌重写整个歌曲数组。新增 SQLite 驱动的包体/构建成本应在实施时记录，不承诺它比当前 JSON 一定更快。

建议表：

```text
tracks(provider, platform_id, title, artists_json, album_json, duration_ms, cover_json, playback_identity_json)
playlists(id, name, created_at, updated_at)
playlist_items(entry_id, playlist_id, provider, platform_id, order_key, added_at)
favorites(provider, platform_id, added_at)
play_history(id, provider, platform_id, started_at, position_ms, played_ms)
lyric_offsets(provider, platform_id, offset_ms)
sources(id, metadata_json, revision, enabled, imported_at)
playback_session(version, queue_json, position_ms, repeat, shuffle)
schema_migrations(version, applied_at)
```

歌曲主键为 `(provider, platform_id)`；歌单条目有自己的唯一 ID。长列表分页/虚拟化，不能每一帧查询 SQL。写入串行化/短事务，队列和收藏更新先在服务层完成，再向 UI 发布结果。播放历史根据真实开始/播放进度记录，不能点击失败的歌曲也记成“已播放”。

迁移原则：

- 新应用 ID、新数据目录；旧目录只读导入，不继续自动搬走原应用的数据。
- 导入旧 `session.json` 时把数字 ID 转成 `wy` 字符串身份，校验队列/order/position；恢复默认暂停，仅还原状态，用户播放时再解析。当前 `Restore -> loadAt(..., false, ...)` 仍请求歌词、封面和音频（`player.go:633–668,796–811`），新版本要去掉这项隐式联网。
- 保留音量、主题、音效和歌词偏移等有用设置，删掉账号、播客、评论相关配置。
- 旧会话不包含完整云端收藏/歌单，因此不能承诺本地直接迁出网易账号所有歌单；可恢复的数据以实际文件为准。
- 不自动删除 Cookie、模型、缓存或原数据；在新版本验收与备份后由用户决定清理。
- 备份歌单/收藏/设置采用有版本的可读文件，导入校验、事务写入，损坏文件不破坏当前库。LX 自身备份导入需实际样本再确定格式，不凭空宣称兼容。
- 当前 session 保存包含主线程上的整队列 JSON 与磁盘写入（`internal/app/session.go:27–69`）；新版本主线程复制必要快照，后台合并/原子提交，退出显式 flush。不能把可变 slice 原引用交给后台后继续修改。

## 10. 播放核心与缓存改造

### 10.1 播放生命周期

保留现有队列、淡变、EQ、FLAC 渐进解码、媒体键与 seek 手感。将网络依赖注入为 Resolver / Lyrics / Artwork，不再在 player 内 import netease。

每次播放操作建立 generation 与 context，状态明确区分 `Idle / Resolving / Buffering / Playing / Paused / Seeking / Failed`。换歌时先撤销旧播放请求和无消费者任务，再提交新请求；旧结果即使晚到也不能操作新的输出流。界面构建只读取状态快照。

封面、歌词与可选分析不阻塞可听音频。输出流只在完整初始化成功后交付主线程；音频 callback 内不跑 JS、HTTP、SQL、图片解码或大对象分配。主线程不等待网络、文件下载或 seek 解码；先核实当前 MyGo Seek 实现，再决定放入播放器工作队列的具体方式。

第一版不添加自动跨平台换歌、无限换源或未经用户许可的音质降级。解析失败时保留当前请求音质，展示可执行原因和手动重试/换音质入口；将来若开放自动降级，必须是明确可设置的策略。

### 10.2 元数据和解码

- 播放 URL 返回后使用真实 GET 响应取得 Content-Length/Content-Type，并按文件签名探测；不能只信扩展名。
- 未知大小使用不定进度；时长以曲库/解码头为依据，后续修正不能造成进度条跳错。
- 当前明确实现 MP3/FLAC；AAC/M4A/其他容器先用实际响应样本验证需求，再决定是否增加解码器，不先捆绑整套 FFmpeg。
- 对服务器不支持 Range、返回 200 代替 206、签名 URL 过期、重定向和下载中断分别处理。Range 不是加一个 header 就完事，需校验偏移/长度与解码定位。
- MP3 CBR/VBR、FLAC seektable/无 seektable、未知大小、尚未下载位置均有独立验收样本。
- 缺少 Gain/Peak 不展示“已经响度均衡”；先原样播放，可选离线分析是另一项功能。
- 预取以当前/下一首为边界，前台解析优先；预取数量与开启状态可配置，不预先解析整张歌单消耗付费接口。

### 10.3 三种缓存分开

| 缓存 | 内容 | 键与失效 |
| --- | --- | --- |
| 解析缓存 | 短期签名 URL | SourceID + revision + provider + id + requested quality；遵守过期，不把它写进会话永久复用 |
| 音频缓存 | 完整有效文件/下载中的临时文件 | 平台身份 + 音源版本/资源标识 + 实际格式/音质；不直接拿 URL 当唯一身份 |
| 图片/歌词/搜索缓存 | 可再生元数据和图像 | 平台身份/URL/尺寸/内容版本；分别有容量和 TTL |

临时文件使用唯一任务/资源键，完成并验证后原子提交；并发同一资源合并且正确引用计数。没有 size 时也不能把半截下载当完整缓存。淘汰跳过正在播放/下载的文件，启动清理孤立临时文件；失败下载不把空文件登记为命中。

图片增加按解码后内存预算的 LRU，而非仅压缩文件大小；Bitmap/Canvas 的最终释放遵守 MyGo 原生资源和主线程生命周期，不能在后台 goroutine 随手销毁。歌词和搜索缓存也不能因用户搜索很多关键词无限增长。

## 11. 界面和动画：保留现有优势，减少无效工作

当前已经有值得保留的设计：

- 歌曲列表 `ui.List` 只构建可见行，稳定 key 很重要。
- Now Playing 用 `AnimatePose`，注释及实现表明转场走绘制层；完全覆盖后停止构建底层页。
- 进度条按像素推进预约，时间文字按秒更新，不对整个窗口无条件 60 FPS。
- 背景有 GPU/CPU 和 ReduceMotion 分支，暂停后速度渐停，并非无条件一直动。
- `lyricGlide` 用最终滚动位置加视觉 lag 做歌词跟随，已处理用户接管和 ReduceMotion（`internal/app/ui_nowplaying.go:565–636`），可继续复用。
- `perf_test.go` 已有帧预算测试，但明确指出 `FramePending` 不覆盖 `After/Painter.After`；这些测试不能单独证明真实帧率或待机功耗。

还有一个需要针对性测量的边界：`timedLines` 当前遍历全部歌词行，活动逐字行会每 40 ms 预约一次（`ui_nowplaying.go:473–524`）。它不像歌曲 `ui.List` 那样已经虚拟化；长歌词要测构建成本，再决定采用窗口化渲染或行级缓存，不能把“歌曲列表已虚拟化”泛化为所有滚动区都没有开销。

建议布局：左侧“搜索 / 我喜欢 / 最近播放 / 我的歌单 / 音源管理”，次级提供榜单，底部设置。首页是本地资料库；空状态引导导入音源，不显示登录、会员、社交或推荐流。正在播放保留封面、歌词、队列三大内容；歌词模式和高开销特效放在独立的外观/动态设置。

动画优化原则：

1. 不把“更丝滑”简化成缩短所有 duration。先保留当前 450 ms、Bounce 0.08 的 Now Playing 参数，用录屏/帧日志检验节奏和掉帧（`ui_nowplaying.go:15–18`）。
2. 优先 transform/opacity 和绘制缓存，避免每帧改变布局、重建长列表、重解码封面、重算歌词全文。
3. 转场可打断、可反向；连续开关不能依靠固定超时释放新一轮动画仍使用的资源。
4. 动态背景按自己的刷新预算跑，交互动画跟随显示器和框架节奏；不把所有画面硬锁 120 FPS。
5. 遮挡、最小化、隐藏、暂停、软件渲染、ReduceMotion 都有明确停帧/静态策略；后台只保留播放需要的工作。
6. 提供动态效果强度、背景动画和高级粒子开关，尊重系统减少动态效果；参数允许恢复默认。基础播放不依赖特效开启。

建议验收预算（目标，不是当前实测成绩）：60 Hz 下关键转场 frame time P95 ≤16.7 ms，120 Hz 下轻量交互 P95 ≤8.3 ms；同时记录 P99 和最长卡顿，不能只报平均 FPS。需约定同一设备、窗口大小、DPI、GPU 和数据集；不以低配机器也必须达到任意固定值作无依据承诺。

## 12. 设置：由你控制，不用隐式策略代替选择

建议保留或新增：

- 默认平台、当前音源、每个平台优先音质；音质列表来自当前源的实际能力。
- 自动降级/自动换源默认不启用；需要时明示规则、顺序和恢复默认。
- 音频磁盘缓存上限与路径、清理缓存；图像缓存和预取的高级选项。
- 音量、手动 EQ、可选自动分析；缺数据时不伪装响度均衡。
- 主题、歌词显示/字号/翻译、逐曲歌词偏移、动态效果和减少动态效果。
- 网络代理/超时等高级选项若开放，标明作用于曲库、宿主还是音频下载。你的脚本内部 5/10 秒预算不会因为改应用 HTTP 超时自动改变，不能做无效设置。
- 全局恢复默认、分组恢复默认、导出/导入设置；恢复设置不删除歌单或音源。

不把 Key 轮换、脚本内部缓存等已由脚本管理的实现细节再做一套看似可调、实际不生效的 UI。

## 13. 实施顺序与每阶段完成条件

### A. 先验证真实接入，不先大改界面

完成：锁定 Go/MyGo 开发环境、建立可重复构建；对当前功能取得真实基线；用 Goja worker 跑原始脚本并通过上述合同探针；在主程序通过统一 TrackRef 和 Resolver 跑通 `wy` 搜索、歌词、解析、MP3/FLAC 播放、切歌、seek、恢复。

退出条件：使用**原始 JS 不改 Key/业务逻辑**可完成一条真实歌曲链路；不显示登录，不再被网易 VIP UI 权限拦住；明确真实返回的元数据和格式。真实付费接口请求应使用用户明确选择的歌曲及音质，不自动跑批。

### B. 本地资料库与账号业务清退

完成：统一身份迁移、SQLite 收藏/歌单/最近播放、无账号启动、队列会话迁移；删除第 2 节明确的业务与全部后台链路，整理设置、菜单和路由；禁用原更新源。

退出条件：离线也能管理资料库；所有保留入口不再弹登录；收藏/歌单/历史均落本地；旧数据可回滚；不再调用旧账号业务接口或后台模型下载。

### C. 五平台与完整音源管理

完成：另外四个平台的搜索/歌词/封面适配；音源导入、替换、切换、禁用和诊断；平台能力与请求音质驱动 UI；数据与缓存全面采用复合身份。

退出条件：5 平台的实际歌曲标识正确，至少每种实际音频编码有真样本，声明的 32 组参数做明确的成功/不支持/服务失败分类，不能把“参数被接受”当作“全部可播”。

### D. 播放核心与性能收口

完成：移出自动 EQ 关键路径、任务取消/过期处理、下载与缓存完整性、未知长度与 seek、图像/查询缓存预算、后台与遮挡停帧。

退出条件：快速切歌/重复导入/网络失败/缓存驱逐不泄漏文件、任务或原生资源；关闭缓存/磁盘失败不造成无界内存退化，清空时下载完成不重新填回；定时器重设与 DSP 生效一致性验证通过；前后台和长队列验证通过；与 A 的同环境基线对比，给真实数据。

### E. 交互统一与可安装交付

完成：新导航、空态、错误态、来源/音质标识、快捷键、无障碍焦点和动画中断；独立应用 ID、更新和发布元数据；打包主程序与隐藏启动的 source-host。

退出条件：Windows 可安装/便携包、版本与哈希、使用说明、迁移/备份说明、测试与性能记录；干净用户目录安装后能自行导入你的脚本使用，不需要 Node/Go 环境。其他操作系统另行构建验证，不拿 Windows 结果代替。

阶段 A 提供可用中间结果，C 完成前不宣称已经做成五平台播放器。当前没有时间实测数据，不给虚构的人日或首播提升比例；以这些退出条件控制范围。

### 14.2 UI 与真实运行
